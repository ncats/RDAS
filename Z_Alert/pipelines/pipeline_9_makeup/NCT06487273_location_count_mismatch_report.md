# NCT06487273 Location Count Mismatch Report

Generated: 2026-08-31

## Question

The Memgraph query below returns 56 locations for clinical trial `NCT06487273`, but the ClinicalTrials.gov study page/API shows 57 locations.

```cypher
MATCH p = (d:ClinicalTrial {nctId: 'NCT06487273'})-[]-(l:Location)
RETURN count(l);
```

## Summary

The 56 count is caused by graph deduplication, not by a missing source location row.

Both the live ClinicalTrials.gov API payload and the local MySQL `clinical_trial_unique.studies` JSON contain 57 location rows. The clinical-trial graph loader converts those 57 rows into 57 valid location chunks, but two Amiens, France locations generate the same `Location._idx_key` because the code uses `geoPoint` latitude/longitude as the preferred location identity when coordinates are present.

After that, the Cypher writer uses `MERGE` on `Location._idx_key`, so the two source rows become one `Location` node and one `has_trial_location` relationship for this trial.

## Code Path

The active alert pipeline runs clinical-trial graph task 11 from:

- `Z_Alert/main.py`
- `Z_Alert/pipelines/pipeline_2_clinical_trial/task_clinical_trial_graph_11.py`

In `task_clinical_trial_graph_11.py`, locations are read directly from:

```python
contacts_locations_module = protocol.get('contactsLocationsModule', {})
locations = contacts_locations_module.get('locations', [])
```

The location key is built in `_create_location_chunks()`:

```python
loc_idx_key = None
facility = loc.get('facility', None)
if facility:
    loc_idx_key = _make_hash_key(facility)

geo_point = loc.get('geoPoint', None)
if isinstance(geo_point, dict):
    lat = geo_point.get('lat')
    lon = geo_point.get('lon')
    if lat is not None and lon is not None:
        loc_idx_key = _make_hash_key(str(lat) + '' + str(lon))
```

Important behavior:

- The code first creates a hash from `facility`.
- If `geoPoint.lat` and `geoPoint.lon` exist, it overwrites the facility key.
- Therefore, two different facilities at the same rounded coordinates are treated as the same graph `Location`.

The writer query then merges by that generated key:

```cypher
MERGE (loc: Location {_idx_key: location.loc_idx_key})
...
MERGE (ct)-[:has_trial_location]->(loc)
```

Because both Amiens rows have `geoPoint = 49.9 / 2.3`, both map to one `Location` node.

## Root Cause

The current graph model treats `Location` as a deduplicated physical/geographic place, keyed primarily by coordinates when available.

ClinicalTrials.gov counts locations as study site records. Those site records can have different facilities that share the same rounded coordinates. For `NCT06487273`, two separate Amiens facilities share the same `geoPoint`, so ClinicalTrials.gov reports 57 site rows while Memgraph stores 56 unique location nodes.

## Recommended Options

### Option 1: Keep Current Behavior

Use this if `Location` is intended to mean a deduplicated geographic place.

In that case, the Memgraph count of 56 is expected. For reporting, label it as "unique graph locations" or "unique coordinate/facility-derived locations" instead of "ClinicalTrials.gov locations."

Recommended query:

```cypher
MATCH (:ClinicalTrial {nctId: 'NCT06487273'})-[:has_trial_location]->(l:Location)
RETURN count(l) AS unique_graph_location_count;
```

### Option 2: Match ClinicalTrials.gov Site Count

Use this if the graph should preserve every ClinicalTrials.gov location row.

Change the location identity so separate site rows do not collapse only because they share coordinates. For example, include `nctId`, `facility`, `city`, `state`, `country`, and `zip` in the key:

```python
site_identity = f"{nctid}|{facility}|{loc.get('city', '')}|{loc.get('state', '')}|{loc.get('country', '')}|{loc.get('zip', '')}"
loc_idx_key = _make_hash_key(site_identity)
```

This would make the graph count match the source site count for this case.

Tradeoff: `Location` nodes would become trial-site-specific instead of globally shared geographic places.

### Option 3: Add a Separate Site-Level Node

Use this if both meanings are needed:

- Keep `Location` as the shared geographic/place node.
- Add a separate `TrialLocation` or `ClinicalTrialSite` node/relationship for each source location row.

This preserves:

- 57 ClinicalTrials.gov site records.
- 56 unique geographic graph locations.

This is the cleanest model if downstream reports need both "site count" and "unique location count."
